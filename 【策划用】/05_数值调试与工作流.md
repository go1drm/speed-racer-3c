# 05 - 数值调试与工作流

> 让"调参 → 测试 → 改 → 测"循环更快的工具。

## 我们项目自己有的 ⭐⭐⭐⭐⭐

### Tuner UI (本项目自带)
- **位置**: 屏幕右上, F8 唤出
- **作用**: 200+ 参数实时调整
- **优势**: 比 Inspector 强 (实时生效 + 三级分类 + tooltip + 范围/步长可视化)
- **劣势**: 自己写的, 不是插件

### 文件日志
- **位置**: `%APPDATA%\Godot\app_userdata\简单飞车试验场\logs\godot.log`
- **作用**: 看历史 print 信息
- **使用**: 我用 PowerShell `Get-Content -Tail` 读 (我会帮你读)

## 通用调试插件 ⭐⭐⭐⭐⭐ 🟢

### Reactive Inspector (重点推荐)
- **GitHub**: https://github.com/cangiabaresi/godot-reactive-inspector
- **作用**: @export 变量在游戏运行时改 → 立刻生效, 不停止重启
- **赛车游戏意义**:
  - 不用每次跑 → 退出 → 改 → 跑
  - 调反打角速度 / 油门曲线时, 跑着改
- **配合 Tuner**: 一些"我们 Tuner 没暴露的"参数也能调

### Godot Debug Menu
- **GitHub**: 搜 "godot 4 debug menu"
- **作用**: 游戏内菜单切换调试模式 (无敌 / 慢动作 / 显示物理 / 显示 FPS)
- **赛车游戏意义**: 测撞墙物理时开"无敌+慢动作"调反弹

### Profile Tools (内置 Profiler)
- **位置**: Godot 编辑器底部 Debugger → Monitor / Profiler
- **作用**: 看 CPU 各函数耗时 / 内存 / 渲染管线
- **赛车游戏意义**: 找帧率掉的瓶颈

## 物理可视化 ⭐⭐⭐⭐ 🟢

### Visible Collision Shapes (内置)
- **位置**: Debug → Visible Collision Shapes
- **作用**: 显示所有 Area / Body 碰撞体
- **赛车游戏意义**: ⭐⭐⭐⭐⭐
  - 检查加速带 Area3D 范围对不对
  - 调试墙体碰撞形状
  - 现在我们项目对了

### Show Physics Process Time
- **作用**: 显示物理帧耗时
- **赛车游戏意义**: 检测物理瓶颈

### DebugDraw3D / godot-debug-draw-3d
- **GitHub**: https://github.com/DmitriySalnikov/godot_debug_draw_3d
- **作用**: 在 3D 场景里画线 / 球 / box (调试用)
- **赛车游戏意义**: ⭐⭐⭐⭐⭐
  - 画速度向量
  - 画 RayCast3D 落地射线
  - 画法线 / 漂角
  - 画 forward / velocity 之间的差

```gdscript
# 例: 画车的速度向量
DebugDraw3D.draw_arrow(global_position, global_position + linear_velocity, Color.RED, 0.1)
# 画反打回正目标方向
DebugDraw3D.draw_arrow(global_position, global_position + v_dir * 5, Color.GREEN, 0.1)
```

**实测推荐度**: 这是**必装**, 你一旦用过再也回不去 print 调试

## 关卡设计辅助 ⭐⭐⭐⭐ 🟢

### Editor Camera Bookmarks
- **作用**: 编辑器里标记常用相机视角, 快捷键切换
- **赛车游戏意义**: 调赛道时快速从俯视切到第一人称 / 起点 / 终点

### Scene Manager Plus
- **AssetLib**: 搜 "Scene Manager"
- **作用**: 编辑器顶部加场景切换下拉菜单
- **赛车游戏意义**: 在多个赛道场景间一键切换 (你提的需求)

### Scene Tree Recorder
- **作用**: 录制场景在某个时间点的状态, 之后能回放
- **赛车游戏意义**: 录制 bug 现场, 反复看怎么发生的

## 版本控制工作流 ⭐⭐⭐⭐⭐ 🟢

### Git (你已经在用)
- 建议 commit 频率: 每天至少 1 次, 每个功能 1 次
- 赛车游戏特别提示:
  - 二进制资源 (FBX, .png, .ogg) 用 Git LFS, 否则 .git 文件夹会爆炸
  - .gdignore 加上 `.godot/` `*.import` `addons/某些` 避免冲突

### Git LFS (大文件)
- 二进制资源用这个
- 设置: `git lfs install` + `git lfs track "*.fbx"`

### .gitignore 推荐 (针对 Godot 4 项目)
```
# Godot 4 自动生成
.godot/
*.translation
*.import

# 平台特定
export.cfg
export_credentials.cfg

# 系统
.DS_Store
Thumbs.db

# IDE
.vscode/
*.code-workspace
```

- **GitHub**: https://github.com/bitwes/Gut
- **作用**: 单元测试框架
- **赛车游戏意义**: 可以测试"集气数学" / "叠喷判定" 等纯数学逻辑

- **赛车游戏意义**: 改完反打后, 跑一遍录制好的"标准漂移测试", 看车是否走出同样的轨迹

## 工作流推荐顺序

### 一天的调参循环 (现在)
1. 打开 Godot
2. 跑游戏 (F5 或运行当前场景)
3. F8 调出 Tuner
4. 改一个参数, 试 30 秒
5. 觉得不对 → 改另一个
6. 觉得对 → Tuner 里点保存
7. 退出 → 看日志确认无错
8. (我读日志, 给反馈)
9. 改代码逻辑 (我写)
10. 重复

### 一天的内容迭代 (下一阶段)
1. Blender / 资源站找模型
2. Godot 导入 → 预览 → 调材质
3. 拖到赛道场景里
4. 跑游戏看效果
5. 调位置 / 缩放 / 物理
6. commit

### 上线前打磨循环
1. 录制 30 秒高质量游玩
2. 反复看, 找"假"的地方
3. 改 (音效 / 视觉 / 手感)
4. 再录, 再看
5. 直到自己看着不出戏
